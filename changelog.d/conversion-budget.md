- 新增: `AIG_CONVERSION_BUDGET`（默认关闭）为跨协议互转（矩阵翻译路径）的单次回复加上工作预算。动机：失控生成（max_tokens 配错、模型循环、单调用工具狂奔）此前会把无边界的翻译 CPU 和 egress 打进 isolate——矩阵翻译与客户端中继都没有自己的输出上界。关闭时矩阵路径与 v0.1.3 逐字节一致。
- 新增: 预算维度（`AIG_CONVERSION_*` 各项均可调，默认 400 事件 / 128KB 输出 / 200 工具事件 / 64KB 单工具参数 / 非流收集 128KB / 每次回复报告的 output tokens（默认 0 表示不启用））。计数单位：解码 IR 事件数；翻译输出长度（UTF-16 码元，ASCII 下约等于字节；chunk 协议封装开销由事件数上限间接约束）；工具事件为 tool_start 与 tool_args 合计数；单参数上限作用于当前打开的工具调用。
- 新增: `AIG_CONVERSION_BUDGET_MODE` 决定超限行为：`error`（默认）在流内以网关错误帧收尾——OpenAI Chat 客户端发 `data: {"error":...}` 加 `[DONE]`，Anthropic 客户端发 `event: error` 加 `api_error`，Responses 客户端发 `event: error` 加 `type:"error"`（message 与 code 均为 `conversion_budget_exceeded`）；对象收集路径返回带同名 code 的 502。`truncate` 模式改为渲染一条良构短回复（finish_reason=length / stop_reason=max_tokens / response.incomplete），请求按正常交付记账。错误模式下这条尝试按中性收尾记账（kind=conversion_budget、counted=false、不冷却节点、也不旋转——换节点只会重新生成同一份超限回复并重复计费），但物理上游尝试已产出的 token 仍经未交付记账写入成本口径；Tier 1 配额租约按实际观测用量结算。
- 新增: `AIG_CONVERSION_PREFER_NONSTREAM`（默认关闭）让非流式客户端保留自己的 stream flag，跨协议转换时允许上游直接返回单个 JSON 体（跳过 SSE 解析；缓冲读取边界已覆盖该形态）；流式客户端仍旧向上游强制 stream:true。
- 变更: 矩阵路径不再叠加二次扫描：`AIG_STREAM_PASSTHROUGH` 开启时，矩阵翻译后的客户端流改用与原生路径相同的逐字节 relay（矩阵已翻译一次，对客户端流再做一次 decode 与标记扫描纯属浪费 CPU）；交付 token 记账经 collector 的 usage 回调保留。
- 变更: 流式文本快路径（绕过 IR 直拼字段映射）经评估推迟——上游 SSE 载荷必须 JSON.parse（错误、usage、工具检测都依赖它），IR 层只是每事件一次的模板级字符串映射，快路径只省这一层小开销；而同一回复里 thinking、工具、usage 与纯文本交织，绕过 IR 需要在三个有状态编码器之外再造一套索引与序列簿记，正确性风险高于收益。本行动的预算上限先行封住矩阵路径的最坏 CPU，快路径留待有实测 CPU 数据支撑时再评估。
