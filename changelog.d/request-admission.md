- 新增 `AIG_REQUEST_ADMISSION`（默认关闭，行动 4：请求准入/并发预算，一次性开合整套守卫）。关闭时与 v0.1.3 逐字节一致：无并发门、chunked 按全量 body 上限计费与读取、`max_attempts` 原样、`AIG_REQUEST_HEDGE_MAX` 默认 1。
- 并发门：每个 isolate 内并发**带 body** 的请求超过 `AIG_ISOLATE_MAX_IN_FLIGHT`（默认 32，0=禁用）时，新请求立收 503（`gateway_concurrency_exhausted`，`Retry-After: 1`）。无 body 请求（/health、/metrics、/models、dashboard）永不因此被拒——最忙的时候监控页面反而必须可读。动机：所有 admitted 请求共享 isolate 的单 CPU 线程与 ~128MB 内存，突发流量若不加门，会让**所有**在飞流一起变慢直到 isolate 被回收（连带丢掉全部已学习的 Tier 1 状态）。
- chunked 计量：无可用 Content-Length 的请求体，其**准入计费与实际读取上限**统一为 `AIG_CHUNKED_BODY_MAX_BYTES`（默认 512KB，可调 16KB–32MB），替代旧行为按 `AIG_REQUEST_BODY_MAX_BYTES`（默认 20MB）的全量计费——旧行为在预算忙时几乎拒绝掉全部 chunked 请求（突发 API 流量的常态是分块上传 JSON）。带 Content-Length 的请求体保持"按声明值计费 + 全量读取上限"不变。设计取舍（changelog 注明）：**放弃渐进计量（先预留 64KB 再随读随补）**——512KB 的 worst-case 计费本身已足够便宜（32MB 预算可容纳 64 个并发 chunked 请求），而"原生 512KB / 跨协议 256KB"的分型在读取时点无法区分（协议回退只有在预检通过后才可能发生），故收敛为单一可调上限；读取时点没法区分的语义差异改由部署方调节，不在代码里猜。
- attempts 上限：policy 解析后按流式模式做硬上限——流式 `AIG_STREAM_MAX_ATTEMPTS`（默认 2）、非流 `AIG_NONSTREAM_MAX_ATTEMPTS`（默认 3），超出部分被裁剪（显式配置的 operator 可调高这两个值重新放宽）。动机：第 4+ 次尝试的杠杆是向整个节点池扇出——每次尝试至少一次上游 dispatch 计费——而流式尝试在客户端流提交后**永远无法再重试**。
- hedge 缺省：`AIG_REQUEST_HEDGE_MAX` 的**默认值**由 1 切换为 0（显式设置永远优先，两侧一致）。hedge 竞速是一次无论如何都会计费的额外上游 dispatch，免费层容量下默认关闭；需要竞速的调用方显式设回。
